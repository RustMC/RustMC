# Testing strategy

M0 unit tests validate schema, values, malformed input, and unknown fields. CLI integration tests use isolated temporary directories to exercise help, version, no-argument status, valid and invalid configuration, and usage errors. They require no account, network, Minecraft installation, or private files. Run `cargo test --workspace --locked`.

M1 adds unit checks for loopback-only configuration, range and cross-field validation, pre-bind shutdown, and bind conflicts. Process integration tests use an ephemeral loopback port and emitted events to test admission limits, byte and idle/lifetime closures, SIGINT/SIGTERM, socket cleanup, and exit codes. They send no Minecraft packets, require no credentials, and avoid fixed ports and timing sleeps. The license policy has synthetic failure tests and checks every locked dependency declaration in CI.

Later protocol tests need exact edition versions, malformed-input fixtures, authentication scenarios, and real client evidence. Gameplay needs versioned black-box observations. A future single-writer reference executor is an oracle for parallel equivalence, with replay recording initial state, rules/data, seed/random state, admission, ordered intents, and external results. Repartition, same-tick boundary, migration, and crash-recovery tests should reject divergence. None of these later gameplay/protocol tests exists in M1.
