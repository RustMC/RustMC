# Testing strategy

M0 unit tests validate schema, values, malformed input, and unknown fields. CLI integration tests use isolated temporary directories to exercise help, version, no-argument status, valid and invalid configuration, and usage errors. They require no account, network, Minecraft installation, or private files. Run `cargo test --workspace --locked`.

M1 adds unit checks for loopback-only configuration, range and cross-field validation, pre-bind shutdown, and bind conflicts. Process integration tests use an ephemeral loopback port and emitted events to test admission limits, byte and idle/lifetime closures, SIGINT/SIGTERM, socket cleanup, and exit codes. They send no Minecraft packets, require no credentials, and avoid fixed ports and timing sleeps. The license policy has synthetic failure tests and checks every locked dependency declaration in CI.

M2 discovery tests use independently written Java status and Bedrock UDP ping byte sequences; no proprietary assets or copied server fixtures are checked in. They cover partial Java frames, state and size rejection, UDP magic and datagram rejection, version reporting, shared local port, and shutdown. The owner's Java 26.3 client displayed the RustMC status entry on 29 September 2026; Bedrock 1.26.51 client observation remains open. The opt-in Java preview has codec and process tests for version-gated login, random session UUID shape, and known-pack negotiation. A real 26.3 client decoded login success, loaded local registry/tag metadata, and entered Creative terrain preview. RustMC generated and encoded chunks that the client visibly rendered, including at a configured 32-chunk view. Unit tests cover seed/order repeatability, eight biome labels, negative coordinates, boundary decoration, movement coordinate validation, and one-batch admission. Authentication, authoritative block/inventory actions, persistence, full biome parity, and Bedrock play remain absent. Real-client movement into new chunks and rejoin still need explicit test evidence. Gameplay needs versioned black-box observations. A future single-writer reference executor is an oracle for parallel equivalence, with replay recording initial state, rules/data, seed/random state, admission, ordered intents, and external results. Repartition, same-tick boundary, migration, and crash-recovery tests should reject divergence.
