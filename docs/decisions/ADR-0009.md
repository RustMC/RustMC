# ADR-0009: Versioned local discovery endpoints

Status: **Accepted for M2 discovery only** (29 September 2026).

## Context
M1 established a bounded loopback supervisor. M2 must answer edition-specific discovery without suggesting login or world readiness. Mojang's current Java release metadata identifies 26.3 / protocol 777. Its newest published stable Bedrock protocol schema identifies 1.26.51 / 2193, while a newer 26.52 hotfix exists without a matching schema at this check. See [compatibility](../COMPATIBILITY.md#m2-discovery-targets-checked-29-september-2026).

## Decision
Keep separate Java TCP status and Bedrock UDP unconnected-ping codecs. Bind both to one loopback IP and numeric port; port zero lets TCP select a port before UDP binds it. Reject the whole startup if either bind fails. Reuse M1's finite connection, byte, timeout, and accept budgets. Cap a Java frame at 4096 bytes and a Bedrock datagram at 512 bytes. Report discovery readiness separately from login and world readiness. Return static, truthful status text with zero players and no login claim. Do not implement authentication, sessions, compression, or play in this slice.

## Consequences and verification
The single supervisor remains a development design, not a capacity claim. UDP's unconnected ping has no client game version, so its response cannot validate a Bedrock client's version. Synthetic codec and loopback process tests verify bounded behavior, both transports, malformed input, and shutdown; real-client discovery remains an explicit open gate. If client observation disagrees with the constructed field layout, revise the codecs and document the observation before marking compatibility tested.
