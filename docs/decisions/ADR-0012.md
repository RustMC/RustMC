# ADR-0012: Local Java registry metadata

Status: **Accepted for the loopback Java 26.3 preview** (29 September 2026).

The matching client owns the vanilla core pack. RustMC negotiates that exact
pack and sends registry identifiers with omitted definitions, plus registry tag
membership. Missing tags make otherwise valid configuration fail to load.

A preparation script verifies the official server archive's published SHA-1 and
version, then produces a local metadata manifest from its identifiers and tags.
Static numeric IDs come from the official data generator's registry report.
The manifest and archive are not distributed with RustMC. This does not license
Minecraft data under Apache-2.0, implement the vanilla rules, or copy a server's
implementation. The Rust packet encoder and validation are independently written.

The manifest is capped at 1 MiB, with explicit registry, tag, entry, and ID
limits. Entry IDs retain the listed order, and tags are checked against their
registry. A connection's pending output is capped at 1 MiB. Without a manifest,
the earlier login experiment stops after known-pack negotiation. Unrecognized
packs are rejected; RustMC does not substitute guessed registry definitions.

On 29 September 2026 the running Java 26.3 client accepted the complete registry
and tag exchange, sent configuration acknowledgement, and displayed “Joining
world…”. This is configuration evidence only; no play world or chunks yet.
