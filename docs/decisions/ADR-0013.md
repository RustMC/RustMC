# ADR-0013: Natural-looking local preview regions

Status: **Accepted for the Java 26.3 preview only** (29 September 2026).

## Context

The first biome prototype chose a biome independently for each square 128-block
region. A real 26.3 client showed a conspicuous checkerboard. The requested
preview needs recognisable terrain while remaining deterministic and independent
of any other server's implementation.

Mojang describes modern world generation as a combination of terrain, climate,
biomes, and transitions; it also documents 26.3 changes to noise settings and
material rules. These are compatibility and visual facts, not an implementation
template: [Mojang's Overworld description](https://www.minecraft.net/en-us/article/new-world-generation-java-available-testing),
[biome overview](https://help.minecraft.net/hc/en-us/articles/360046470431-Minecraft-Types-of-Biomes),
and [26.3 snapshot notes](https://www.minecraft.net/en-us/article/minecraft-26-3-snapshot-10).

## Decision

RustMC's local preview continues to derive results from its seed and world
coordinates. It bends coarse region coordinates with independently written
integer lattice noise and selects the nearest jittered site. Eight labelled
surface regions receive distinct surface blocks and tree density or type:
plains, forest, desert, snowy plains, taiga, savanna, jungle, and badlands.
The Java adapter samples biome identifiers at each 4-block horizontal cell;
chunk and biome boundaries are derived from world coordinates, regardless of
request order. The 32-chunk view remains opt-in, sends one acknowledged batch
of up to 16 chunks at a time within a 768 KiB encoding budget, and retains only
the coordinates in view. Creative mode and a
higher client fly speed are for inspection. World interaction is still absent.

## Limits and tests

This is **not vanilla 26.3 world generation**. It does not cover all vanilla
biomes, oceans, caves, structures, climate rules, mob spawning, saves, or
lateral light propagation. The biome labels tell the client how to tint and
render the preview, not that their full vanilla rules exist. Tests cover all
eight regions, coordinate stability, request-order independence, negative
coordinates, chunk-edge tree decoration, bounded view and batch admission.
Direct client observation must establish the displayed result separately.
