# Java 26.3 fixed-seed comparison worksheet

Status: **reference observations complete** (30 September 2026). This is a
research procedure and a record of measured differences, not a vanilla-parity
claim or a change to the M3/M5 gates. The current RustMC generator is
independent and intentionally differs from vanilla. Start with observable
surface results before proposing an algorithm.

## Reference setup

The intended reference is a clean, licensed **Minecraft Java 26.3** client with
no world-generation mods or data packs: a new Creative single-player world with
the default world preset and seed `2026`, commands enabled for repeatable
navigation. Mojang documents [Java 26.3](https://www.minecraft.net/en-us/article/minecraft-java-edition-26-3),
[commands and their permission setting](https://www.minecraft.net/en-us/article/minecraft-commands),
and the [F3 debug options](https://feedback.minecraft.net/hc/en-us/articles/48913133328013-Minecraft-Java-Edition-26-3).

### Exact instance used for the observations

The observations below were taken by the project owner in a locally hosted
single-player world. It is *not* a stock launcher profile, so the deviation is
recorded in full:

- Launcher: Modrinth App (Flatpak), profile named "3".
- Minecraft **26.3** on **Fabric Loader 0.19.5** (from the client log line
  "Loading Minecraft 26.3 with Fabric Loader 0.19.5").
- Installed mods: `fabric-api 0.161.0+26.3` (library only) and a client-side
  fly-speed mod. Neither adds or changes world generation; no worldgen mod is
  present.
- Data packs: none. World preset: default. Dimension: `minecraft:overworld`.
- Seed confirmed in-game with `/seed` → `Seed: [2026]`. Cheats enabled so
  `/tp` navigation was possible; no terrain was edited or generated by mods.

Because Fabric Loader and non-worldgen mods were present, these readings are
treated as strong evidence of vanilla 26.3 behavior rather than a certified
clean-room reference; a stock-client re-check is a reasonable future
confirmation step.

## Method

For each of the six fixed X/Z coordinates the owner ran, in-game:

1. `/tp @s <x>.5 <high-y> <z>.5` to arrive above the point, then
   `/tp @s ~ ~ ~ 0 90` to look straight down.
2. Descended (Creative flight) until the crosshair targeted the solid ground
   block directly under the player, clearing any tree canopy.
3. Recorded the F3 lines `XYZ:` (feet position), `Biome:`, and
   `Targeted Block:` (block coordinates and ID) in one screenshot per reading.
   The 26.3 debug options screen (F3+F6) was used to enable the Biome and
   Targeted Block lines, which are hidden by default.

Vanilla "ground Y" is the targeted top solid block's Y (feet Y minus 1 when
standing on it). Where the first pass targeted leaves, a second canopy-clearing
pass re-read the ground; those final readings are the ones recorded here. No
water was above the surface at any of the six points.

Evidence: one screenshot per reading is retained locally by the project owner
(untracked; not committed to keep account names and binaries out of the
repository). SHA-256 of the three canopy-clearing ground readings:


## Result: RustMC baseline vs vanilla 26.3

The RustMC values come from `Generator::height` and `Generator::biome` for
seed 2026, using:

```sh
cargo run -p rustmc-server --example inspect_preview_seed --locked -- 2026 0 0 256 0 0 256 -256 0 0 -256 512 512
```

`preview_ground_y` is the generator's top terrain layer at X/Z, before trees;
it is not a client player Y, ocean surface, or vanilla heightmap. This tool

## Observed mismatch selected for follow-up

**Biome labels disagree with vanilla at every sampled point (0/6), and the
preview reports them under vanilla `minecraft:*` identifiers.** The sharpest
single case is (0, 0): vanilla 26.3 seed 2026 places `minecraft:forest` with a
grass_block surface at Y=117, while the RustMC preview labels the same column
`minecraft:badlands` and generates a red_sand/terracotta surface at Y=71. A
viewer who knows vanilla seed 2026 can therefore misread the preview's biome
line as a (false) statement about vanilla placement.

This is expected behavior per [ADR-0013](../decisions/ADR-0013.md) — the
preview generator is deliberately not vanilla worldgen — so the fix is not to
chase vanilla placement. The focused improvement is to make the divergence
*measurable and regression-proof*: the six comparison readings above are now
pinned by a unit test
(`seed_2026_comparison_points_match_the_published_worksheet`, in
`crates/rustmc-server/src/world.rs`), so any future generator change that
moves a worksheet value must consciously update this worksheet alongside it,
keeping the published comparison honest over time.

## What the comparison can establish

Each matched coordinate shows a specific height, surface-block, or biome
difference. Six points cannot prove whole-world parity — in either direction —
and a matching point could be coincidental. Caves, oceans, structures,
vegetation, lighting, and all remaining biomes need separate evidence. See the
[compatibility matrix](../COMPATIBILITY.md) and [world-preview ADR](../decisions/ADR-0013.md).
